# TapGuard

A Flutter personal-safety app with a real-time AI risk engine. Users pair with trusted contacts via NFC or QR, share their location, and the app continuously evaluates their risk level — flagging falls, late-night deviations, audio distress, and route anomalies.

## AI risk engine — the core feature

The engine continuously evaluates user risk using a **multi-modal TFLite model + hand-tuned heuristic + on-device personalization** architecture.

### Signal flow

```
Raw sensors ──► Feature extractors ──► TFLite model ──► Personalization ──► Decision engine ──► RiskResult
  Accel/gyro       Motion features        risk [0,1]      User baseline        0.5·model + 0.3·anom
  GPS              Location features                        (Hive-persisted)      + 0.15·keyword
  Mic (16kHz)      Audio features                                               + 0.10·hard-rules
  Battery/Net/Time Context features
  Shake phone      Hard rules
```

### RiskResult shape (consumed by the rest of the app)

```dart
enum RiskLevel { low, medium, high }
class RiskResult {
  final RiskLevel level;
  final double score;            // 0..1
  final Map<String, dynamic> factors; // breakdown for UI
  final DateTime evaluatedAt;
  final double modelScore;       // from TFLite
  final double anomalyScore;     // from baseline
  final double keywordScore;     // from audio keyword
  final double rulesScore;       // from hard rules
}
```

The Safety Status screen, SOS auto-trigger, and home tile all consume this single shape. The engine is fully decoupled from the consumers.

## How to run

```bash
# 1. Install Flutter deps
flutter pub get

# 2. (Optional but recommended) train the production models
pip install -r tools/requirements.txt
python tools/train_risk_model.py --output-dir assets/models --quantize int8

# 3. Run the app
flutter run
```

Without step 2, the app runs on the heuristic fallback — still useful, just less accurate.

## Privacy

- All sensor data stays on the device.
- The user baseline is stored in Hive (`user_baseline_v1`).
- Training examples are stored in Hive (`risk_training_v1`) and can be wiped from the Risk Insights screen.
- The mic only runs the 300 KB keyword spotter, not full YAMNet, until a wake word fires. Raw audio is never stored or transmitted.
- SOS SMS go through the system SMS provider (via `sms:` URI), not through any server.
- OneSignal handles push notifications to contacts (with consent).

## Battery budget

Target: ≤5% / hour with all sensors active.

| Sensor | Typical drain | Configurable in |
|---|---|---|
| Motion (accel + gyro @ 50 Hz) | 2.5% / hr | `MotionCollector` |
| GPS @ 1 Hz | 1.5% / hr | `LocationCollector` |
| Mic (keyword spotter only) | 2.0% / hr | `AudioCollector` |
| Battery/Net poll | 0.1% / hr | `ContextCollector` |

The `BatteryProfiler` tracks actual uptime per sensor and exposes a snapshot for telemetry.

## Rollback plan

The `ModelHealthMonitor` watches the TFLite model output for:
- **NaN / infinity** → instant rollback
- **Stuck output** (same value for 30 evaluations) → rollback
- **Divergence from heuristic** (>0.45 difference for 10 consecutive evaluations) → rollback
- **Training imbalance** (>10:1 positive/negative ratio) → rollback

When any of these trigger, the decision engine falls back to the heuristic for the rest of the session. The user sees the status chip flip from `AI MODEL` to `HEURISTIC` + `[rolled-back]`. A `RiskInsights` log entry records the reason.

## Where to extend

- **New risk scenarios** → add to `synthesize_risk_training_set()` in `tools/train_risk_model.py`, regenerate models.
- **New sensors** → create a new `XxxCollector` in `lib/data/services/risk/`, extend `FeatureExtractor`, add fields to `RiskFeatures`.
- **New model architectures** → swap the `RiskModel` body. The `DecisionEngine` only sees `RiskInference`.
- **Cloud sync** → the `TrainingDataStore` already has a clean Hive interface. A future "Sync to cloud" button can export examples as CSV/JSON.
